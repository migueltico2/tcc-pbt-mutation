\textbf{Validade de conclusão.} No Java, as 30 execuções produziram exatamente o mesmo \ms{}, o que reduz o teste de Mann-Whitney a uma comparação com empates em um dos grupos. A diferença, porém, não depende do teste: em todas as execuções o Node.js ficou acima do Java, o que o $\hat{A}_{12}$ igual a zero expressa diretamente. Essa significância vem da repetição de execuções quase idênticas, e não de uma amostra grande de mutantes diferentes: o teste qui-quadrado sobre os mutantes distintos das categorias comuns não indicou diferença ($p = 0{,}25$), o que reforça a leitura de que a diferença prática é pequena. O tempo foi medido em uma máquina virtual de 2 vCPUs; durante parte das primeiras execuções Java houve atividade concorrente leve na mesma máquina (escrita de código e instalação de pacotes), o que explica parte da dispersão do tempo Java e os poucos mutantes classificados como \textit{timeout} nessas execuções.

\textbf{Validade interna.} A maior ameaça é a equivalência entre as implementações. Ela foi tratada com a especificação escrita antes do código e com os cenários compartilhados, mas há diferenças que são próprias de cada linguagem e que não podem ser eliminadas sem descaracterizar o ecossistema: o Java expõe dados por métodos de acesso (\textit{getters}), que o PIT muta, enquanto o JavaScript usa campos diretos; os status do JavaScript são textos que o StrykerJS muta, enquanto os \texttt{enum} do Java não são mutados pelo PIT. A análise ``sem construtores e acessores'' e a análise por categorias comuns existem para isolar esses efeitos. As bibliotecas de PBT também diferem por dentro: o jqwik informou que os casos de borda excediam o número de tentativas, o que torna sua geração muito mais repetitiva que a do fast-check. Isso faz parte do fator estudado (o ecossistema), mas limita a atribuição das diferenças à linguagem em si.

\textbf{Validade de construto.} O \ms{} mede a capacidade de detectar defeitos artificiais, não defeitos reais. Como as ferramentas geram conjuntos de mutantes diferentes \citep{kintis2018tools,monteiro2022tools}, o fator ``ecossistema'' mistura linguagem e ferramenta, e o estudo não separa os dois efeitos. A classificação dos sobreviventes foi feita por uma pessoa, mas as regras estão codificadas e versionadas no repositório, o que permite revisá-las.

\textbf{Validade externa.} A aplicação tem cerca de 300 linhas de domínio em cada linguagem e oito propriedades, e as propriedades verificam o domínio diretamente, sem passar pela camada HTTP. Os resultados não devem ser generalizados para APIs grandes, com persistência real ou com propriedades escritas em outro estilo (por exemplo, comparação com um modelo de referência completo).
